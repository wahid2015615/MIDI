1. PURPOSE
================================================================================

MIDIgen generates Standard MIDI Files (SMF / .mid) from three input modes:

  Mode             Input                         AI (local)   Output semantics
  ---------------  ----------------------------  ----------  ------------------------------------------
  Text → MIDI     Natural-language prompt       Yes         LLM → composition JSON → MidiEngine
  Chords → MIDI   Progression (e.g. C-G-Am-F)   No          Exact voicings from chord symbols
  Notes → MIDI    Line-oriented note list        No          Exact pitch, duration, velocity, tracks

Exports are SMF Type 0 (single merged track) or Type 1 (multi-track with
Conductor). Target DAWs: Ableton Live, FL Studio, Logic Pro, Cubase, Reaper,
Studio One, and other SMF-compatible hosts.

This file is the system-of-record for architecture, contracts, and ops. READMEs
are short setup guides. OpenAPI (/docs) is the live schema (may include field
descriptions not repeated here in full).


================================================================================
2. GOALS AND NON-GOALS
================================================================================

GOALS
-----
  * Produce valid, DAW-loadable MIDI (tempo, meter, programs, channels).
  * Separate creative generation (LLM, text only) from deterministic
    rendering (chords/notes + engine + post-processors).
  * Shared HTTP post-pipeline for all generate endpoints (Studio + REST).
  * Chords and Notes modes do not call the local LLM (exact, offline).
  * Reject empty / fully muted mixes; validate SMF after write.

NON-GOALS
---------
  * Real-time MIDI streaming / Web MIDI.
  * Audio synthesis or sample playback.
  * Auth, billing, or multi-tenant rate limits (local / trusted-network).
  * Guaranteed “perfect” musical AI output (quality varies by model/prompt).

DESIGN PRINCIPLE
----------------
Routers stay thin. Features build a MidiEngine; app/shared/midi_response.py
owns mix, selection, expression, timing, and export helpers so REST modes stay
aligned.

Expression runs BEFORE timing so generated sustain / modulation / pitch-bend
events are also quantized, swung, and optionally humanized.

6. GENERATION PIPELINES
================================================================================

6.1 SHARED HTTP POST-PIPELINE
-----------------------------
Used by POST /generate/text, /generate/text/preview, /generate/chords,
/generate/notes (notes skips step 3).

  Step  Helper                     What it does
  ----  -------------------------  ------------------------------------------------------
   1    apply_score_meta           Time signature + key signature on engine
   2    apply_track_mix            Mute/solo/vol/pan/instrument/channel
                                   Custom Notes labels (e.g. Violin) follow
                                   Melody mute/solo/vol/pan; keep @track
                                   instrument/channel. Melodic roles cannot
                                   use drum kit / drum channel 9.
   3    apply_track_selection      Disable roles the client turned off:
                                   muted=True AND solo=False (cannot resurrect).
                                   Non-mixer-role tracks muted when any
                                   include_* is set (text + chords only;
                                   notes has no role pills — skips this step)
   4    apply_expression_options   CC64 / CC1 / pitch bend on active tracks
                                   (null/omitted expression = no-op)
   5    apply_timing               Quantize, swing, humanize, PPQ
   6    ensure_exportable          Fail if nothing audible remains
   7    send_midi / engine_meta    Export+validate file OR preview JSON;
                                   archive copy under backend/generated/

Response download headers (generate file endpoints):

  X-MIDI-BPM | X-MIDI-Bars | X-MIDI-Tracks | X-MIDI-PPQ | X-MIDI-Key |
  X-MIDI-TimeSig | X-MIDI-Saved-As (archived filename under generated/)


6.2 TEXT → MIDI
---------------

  Flow:
    prompt (+ body overrides)
      → heuristic parse (bars, BPM, key, mood, style, …)
      → merge overrides
      → local GGUF → composition JSON
      → composer → MidiEngine
      → post-pipeline → .mid

  Endpoints:
    POST /generate/text           → MIDI download
    POST /generate/text/preview   → JSON metadata only (same pipeline)
    POST /parse/text              → parse only; returns fields + "detected" map

  Seed: request seed (API / Studio default 42) for LLM sampling reproducibility
  (when llama.cpp honors seed) and for humanize RNG (unless timing.seed is set).
  AI sampling temperature = max(0.0, AI_TEMPERATURE). Seed does NOT force 0.2.

  Cancel: Studio / clients may POST /generate/cancel to abort in-flight
  local GGUF compose at the next safe checkpoint (HTTP 499 on the generate
  request). Optional body ``{"client_request_id": "..."}`` cancels only that
  request (Studio sends the same id on /generate/text). Omit the id to cancel
  all registered generates. Cancel is observed before/after llama.cpp
  ``create_completion`` (mid-inference CPU work may finish before 499).


6.3 CHORDS → MIDI
-----------------

  Flow:
    progression string
      → parse + validate chord tokens
      → exact voicing via parse_chord_symbol (NO LLM)
      → Chords / Bass / Melody(arpeggio) / Drums tracks
      → post-pipeline → .mid

  Chord track notes are the real pitch classes for each symbol
  (Am7 → A C E G, E7b9 includes G#, etc.).

  Progression separators (any one style):
    | pipe/bar     C | G | Am | F   or   | C | G | Am | F |
    - dash/arrow   C - G - Am - F   /   C -> G   /   C → G
    , comma        C, G, Am, F
    whitespace     C G Am F   or one chord per line
  Mixed separators after a primary ``|`` (or ``->``) split are also expanded
  (e.g. ``C | G - Am | F`` → C, G, Am, F).

  Chord qualities (authoritative table: app/core/theory.py CHORD_QUALITY):
    V1  maj, m/min, maj7, m7/min7, 7, sus2, sus4, dim  (+ aug)
    V2  5, 6, m6, add9, madd9, add2, 9, m9, maj9, dim7, m7b5/ø/o, 7sus4, slash C/G
    V3  11, m11, maj11, 13, m13, maj13, 7b5, 7#5, 7b9, 7#9, 7#11, 7b13, 7alt,
        maj7#11, 9b5, 9#5, m7#5
    Aliases: mi, -, power→5, dom7→7, halfdim/ø/o→m7b5, min9→m9, … (see
    CHORD_QUALITY_ALIASES in theory.py). Do not invent qualities beyond that file.

  Role flags: add_melody, add_chords, add_bass, add_drums
  (at least one must be true).

  Implementation: app/features/chords_to_midi/exact.py
  (wired from generate_from_chords — no AI).

  Melody = arpeggio of the same chord tones (harmony-locked).
  Bass = root / slash bass. Drums = simple deterministic groove.

6.4 NOTES → MIDI
-----------------

  Flow:
    notes: string[]
      → line parser → MidiEngine (no LLM / no GGUF)
      → post-pipeline WITHOUT apply_track_selection → .mid
        (still runs: score meta → mix → expression → timing)

  Semantics: Text → exact MIDI events. Pitches, durations, velocities, and
  track directives are honoured 1:1. Chord-tone list order inside one line
  (C4 E4 G4 vs E4 C4 G4) does not matter when notes share the same start beat.

  Grammar:

    Construct              Example
    ---------------------  ---------------------------------------
    Note + duration        C4 quarter | E4 q | G4 half 90
    Same-line chord        C4 E4 G4 q  |  C4 E4 G4 half note 90
    Rest                   rest quarter | r q
    Track directive        @track Melody acoustic_grand_piano
    Alternate directive    #track Bass electric_bass_finger
    Section header         [Chords electric_piano_1]
    Comment                # text  (except lines starting #track)

  Multi-track example (independent beat cursors per track):

    @track Chords electric_piano_1
    C4 E4 G4 q
    F4 A4 C5 q
    @track Melody flute
    G5 e
    A5 e
    @track Bass acoustic_bass
    C2 q
    C2 q

  Same-line pitches share one start beat and one duration (optional velocity).
  Without directives, events use one default Melody-style track.
  Durations: app/core/theory.py (parse_duration).
  Pitches: sharps/flats (C#4, Bb3, …).

  Timing / expression: Studio sends the shared timing + expression objects
  for Notes (and Chords/Text). With humanize=false (Studio default), same-beat
  chord notes export on the same tick. With humanize=true, timing jitter is
  ±humanize_timing beats (default 0.02 ≈ ±10 ticks at PPQ 480) — pitches stay
  correct; this is post-pipeline humanize, NOT AI and NOT the notes parser.


6.5 SHARED STUDIO FIELDS (ALL MODES)
------------------------------------

  After composition, all generate modes may send:
    mix          Mute/solo/vol/pan/instrument/channel
    timing       PPQ, quantize, swing, humanize (+ amounts)
    expression   Sustain CC64, modulation CC1, pitch bend (+ advanced)

  Mode-specific primary input:
    Text     → prompt (+ optional bpm/bars/key/mood/style/tracks)
    Chords   → progression (+ bars_per_chord, add_* role flags)
    Notes    → notes[] (tracks come from @track / #track / [Name] lines)

7. CORE DOMAIN MODEL
================================================================================

7.1 MidiEngine  (app/core/engine.py)
------------------------------------

  Concept               Description
  --------------------  -------------------------------------------------------
  NoteEvent             pitch, start_beat, duration_beats, velocity
  CCEvent               control, value, time_beat
  PitchBendEvent        value (0..16383 center 8192), time_beat
  MidiTrack             name, notes, CC, PB, instrument, channel, mute, solo,
                        volume, pan
  MidiEngine            bpm, time_signature, key_signature, ppq, tracks

Export guarantees:
  * BPM clamped (BPM_MIN..BPM_MAX); non-positive → 120
  * Time signature validated (numerator 1–16; denominator 1|2|4|8|16|32)
  * Same-pitch overlaps → legato (off before next on)
  * Absolute times → delta times; end_of_track padded
  * validate_smf_file after write
  * resolve_export_channels on ACTIVE tracks only

Type 0 vs Type 1:
  * Type 1 (default): track 0 = "Conductor" (tempo / TS / key) + role tracks.
    Default: score meta on Conductor ONLY (SMF 1.0).
    Optional: duplicate_score_meta=true copies meta onto each note track.
  * Type 0: one "Merged" track (all channels / meta together).


7.2 MODULES UNDER app/core/
---------------------------

  Module            Responsibility
  ----------------  -------------------------------------------------------
  theory.py         Note names, durations, harmony helpers
  instruments.py    GM programs, aliases, drum channel 9
  catalog.py        Moods, styles, BPM hints, prompt matching
  timing.py         Quantize, swing, humanize, MPC→delay helper,
                    sustain pair preservation
  expression.py     Sustain / mod / pitch-bend patterns
  smf_validate.py   Post-export structural checks
  engine.py         Score model + SMF build


7.3 ROLES, MUTE, SOLO
---------------------

Canonical roles: melody | chords | bass | drums

Drums: GM channel index 9 (Studio displays as channel 10).

Export rules (matches Ableton-style solo semantics for “what is heard”):

  Situation                              Exported
  -------------------------------------  ----------------------------------
  No Solo on any role                    All enabled non-muted roles
  One or more Solo on                    Only those soloed roles
  Solo + Mute on same role               Solo wins (still exported)
  Role pill OFF (Studio)                 Not exported; S/M cleared in UI
  Mixer Mute on enabled role             Omitted from .mid

  Mute/disable = OMIT from file (not a silent empty track). This is intentional
  export-as-heard behavior.

  When apply_track_selection disables a role (include_*=false), solo is cleared
  so Solo cannot resurrect a disabled role.

8. SHARED REQUEST OPTIONS
================================================================================

Defined in app/shared/schemas.py; mirrored in frontend types.


8.1 TrackOptions (text mode)
----------------------------

  { "melody": true, "chords": true, "bass": true, "drums": false }

When the ``tracks`` object is present, omitted role keys default to **false**
(not schema class defaults), so ``{"melody": true}`` enables melody only.
At least one role must be true.

Default when ``tracks`` is omitted entirely: melody+chords+bass on (prompt /
service defaults).


8.2 Chords role flags
---------------------

  add_melody | add_chords | add_bass | add_drums   (booleans)


8.3 TrackMixOptions
-------------------

Per role (melody/chords/bass/drums):

  mute_*            bool (default false)
  solo_*            bool (default false)
  volume_*          0–127 (melody/bass/drums default 100; chords 90)
  pan_*             0–127 (default 64)
  instrument_*      GM slug or null
  channel_*         0–15 or null (auto); drums forced to 9


8.4 TimingOptions
-----------------

  Field                 Notes
  --------------------  ----------------------------------------------------
  quantize              "1/1".."1/32" or null (API default null = no snap;
                        Studio default "1/16")
  quantize_duration     bool (default true)
  swing                 DELAY FRACTION 0.0–1.0 — NOT MPC percent
                        0 = straight; ≈0.33 = triplet feel
                        Studio: MPC slider 50–75 → delay = (mpc-50)/50
                        Helper: mpc_swing_to_delay() also accepts 50–100
  swing_grid            usually "1/8" or "1/16" (default "1/8")
  humanize              bool (default false; Studio default off)
  humanize_timing       beats jitter (default 0.02)
  humanize_velocity     int jitter (default 8)
  humanize_duration     beats jitter (default 0.01)
  humanize_controllers  also jitter CC / pitch-bend times (default false)
  ppq                   24–9600 (default 480)
  seed                  optional humanize RNG seed (falls back to request seed)

Request-level seed (text/chords/notes schemas): default 42 (not timing.seed).

WARNING: POSTing swing: 66 (thinking “MPC 66%”) is incorrect. Convert first.


8.5 ExpressionOptions
---------------------

  sustain | modulation | pitch_bend — defaults True when an ExpressionOptions
  object is present. Omitted / null expression = no-op (no CC/PB written).
  Studio always sends the expression object.

Optional fine controls (schema defaults):
  sustain_on_value 127 / sustain_off_value 0 / sustain_hold_ratio 0.92
  modulation_value 24 / modulation_interval_bars 2.0 / modulation_accent_ratio 0.5
  pitch_bend_scoop_depth 400 / pitch_bend_interval_bars 4.0 /
  pitch_bend_scoop_beats 0.25

When sustain is enabled, sustain_on_value and sustain_off_value must differ
so pedal pairs stay ordered under quantize/humanize.

Sustain pairs remain ordered under timing even when off_value ≠ 0.


8.6 Export flags
----------------

  file_type                0 | 1     (default 1)
  duplicate_score_meta     bool      (default false)
                           Type 1 only; true = meta on every note track


8.7 Limits
----------

  Parameter         API / engine              Studio UI
  ----------------  ------------------------  -------------------
  BPM               4–300; HTTP ≤0 → 120      same (cleared → 120)
  Bars              1–512 (default often 16)  1–128 UI cap
  bars_per_chord    0.0625–16; total ≤512     same preflight checks
  Time signature    num 1–16; den power-of-2 as listed above
  Beat times        finite; ≤ BEAT_TIME_MAX   Notes rejects Inf/huge
                    (512×16 beats)

9.4 Errors
----------

  Via raise_generate_http / FastAPI:
    400  validation, empty mix, bad progression / notes
    422  Pydantic field errors (loc + msg)
    499  Generation cancelled (after POST /generate/cancel)
    503  Other AIMusicError (e.g. missing model during text compose)
    4xx/5xx other failures mapped with readable detail

  Studio: formatApiDetail() normalizes detail string | array | object.


9.5 CORS
--------

Always allow localhost:3000 / 3001 (and 127.0.0.1 variants).
Default origin regex covers private LAN (10.*, 172.16–31.*, 192.168.*).
Production: set CORS_ORIGINS (comma-separated). Optional CORS_ORIGIN_REGEX
(empty string disables the default regex).

  Path                                  Role
  ------------------------------------  ---------------------------------------
  src/app/                              App Router, layout, globals.css

User flow:
  1. Choose mode (text / chords / notes)
  2. Optional prompt parse (POST /parse/text) auto-fills ONLY detected fields
  3. Health (?probe=1) + /meta/instruments|/styles drive status + dropdowns
     (GGUF / AI ready gate applies to Text mode only; Chords+Notes generate
     without the local model)
  4. Mixer: role pills, Mute/Solo, instruments, channels, vol/pan
  5. Swing = MPC 50–75% (converted before POST)
  6. Generate → download .mid via /generate/text|chords|notes
  7. Cancel (Text) → POST /generate/cancel then AbortController abort

Studio defaults (current UI):
  * Port: http://localhost:3001 (package.json -p 3001)
  * Quantize grid: "1/16"; humanize off; seed 42
  * resolveApiBase(): if page host is LAN and NEXT_PUBLIC_API_URL still
    points at 127.0.0.1, rewrite API host to the page hostname

Studio API usage notes (current UI):
  * Calls: /generate/text|chords|notes, /generate/cancel, /parse/text,
    /health, /meta/instruments, /meta/styles.
  * Does NOT call POST /generate/text/preview (backend-only) or GET /meta/ai
    (AI status comes from /health).
  * UI label "Export preview" is an on-page summary panel, not the preview API.
  * Sends file_type; does NOT send duplicate_score_meta (API default false =
    Conductor-only meta on Type 1).

Env: NEXT_PUBLIC_API_URL (must match backend host/port; rebuild for production).

11. AI INTEGRATION
================================================================================

  Piece            Location
  ---------------  ------------------------------------------------------------
  Client           app/features/generation/ai_client.py
  Config           app/features/generation/config.py
  Prompts          prompts.py
  Orchestration    service.py  (generate_from_prompt; generate_from_chords

  Where the local model is used
  -----------------------------
  * Text → MIDI  (POST /generate/text, /generate/text/preview, CLI text)
  * NOT used for Chords → MIDI (POST /generate/chords / CLI chords) — exact.py
  * NOT used for Notes → MIDI (POST /generate/notes / CLI notes)

  Runtime (llama-cpp-python + Qwen3 GGUF)
  ----------------------------------------
  1. get_ai_config() resolves model path + inference params from .env.
  2. Lazy Llama(...) load/cache (first call 30–90s typical on CPU).
  3. compose_midi_json: ChatML prompt + JSON prefill `{\n  "bpm": `,
     user suffix `/no_think`, free completion (no json_object grammar).
  4. Temperature: max(0.0, AI_TEMPERATURE). Seed passed to create() when
     supported (request seed default 42). Seed does not force 0.2.
  5. Cancel checkpoints honor POST /generate/cancel (Generation cancelled).
  6. Strip <think>…</think>, repair/normalize JSON →
     {bpm, key, time_signature, tracks[]}.
  7. Drop empty-note tracks; require ≥1 playable track.
  8. Debug dump: backend/generated/_last_model_raw.json.txt
  9. composer.composition_to_engine → MidiEngine → HTTP post-pipeline.
 10. After compose, schedule idle unload (MODEL_IDLE_UNLOAD_SECONDS,
     default 120; minimum 5) so RAM is freed when idle.

  Variable                   Notes
  -------------------------  --------------------------------------------------
  LOCAL_MODEL_PATH           Optional path to .gguf
                             (default backend/models/Qwen3-4B-Q4_K_M.gguf)
  LOCAL_N_CTX                Context window (default 4096)
  LOCAL_N_THREADS            Optional; default CPU count − 1
  LOCAL_N_GPU_LAYERS         0 = CPU only
  AI_TEMPERATURE             Default 0.3; no seed override; clamped ≥ 0.0
  AI_MAX_TOKENS              Default 3072
  MODEL_IDLE_UNLOAD_SECONDS  Idle seconds before unloading GGUF (default 120;
                             minimum 5)

Moods / styles must match catalog.py (Studio constants stay in sync).
Default model filename: Qwen3-4B-Q4_K_M.gguf (~2.5 GB).

20. DESIGN DECISIONS
================================================================================

  1. LLM (text) out / engine in — chords & notes stay deterministic.
  2. Shared HTTP post-pipeline — one export path for REST modes.
  3. Expression before timing — automation gets quantize/swing/humanize.
  4. Conductor-only meta by default — SMF 1.0; duplex optional.
  5. Notes without AI — exact, offline, reproducible.
  6. Chords without AI — exact symbol voicings (exact.py).
  7. Validate after write — catch bad files before DAW import.
  8. Parse "detected" map — Studio fills only mentioned prompt fields.
  9. Mute/Solo omit from file — clean export-as-heard SMF.
 10. Active-only channel resolve — muted lanes do not steal channels.
 11. Type 1 default — multi-track DAW editing; Type 0 for interchange.

21. KNOWN LIMITATIONS
================================================================================

Documented intentionally (not silent bugs):

  * CLI skips mix / expression / timing pipeline (§12).
  * Omitted expression/timing on raw REST = no expression/timing applied
    (Studio always sends both).
  * Request seed defaults to 42 unless the client sends null; text mode
    is therefore often seeded for reproducibility.
  * Disabled roles via apply_track_selection clear Solo (cannot resurrect).
  * Text AI length / content may undershoot or vary by seed/model; output
    remains valid SMF. Chords/Notes are exact (not subject to this).
  * TimingOptions.swing is delay fraction; API callers must convert MPC %.
  * Studio bars capped at 128; API allows up to 512.
  * Studio does not send duplicate_score_meta (API default false).
  * Studio does not call /generate/text/preview or /meta/ai (REST still can).
  * No authentication on generate endpoints.
  * Text mode is creative AI — it does not hard-lock every requested bar
    or phrase the way Notes/Chords do.
  * Humanize / swing / quantize run AFTER the exact Notes/Chords builder.
    Event-level tick order inside a same-beat chord may shuffle under
    humanize; pitch set and nominal durations remain correct. Use
    humanize=false for same-tick chord stacks. Default humanize_timing is
    0.02 beats (~±10 ticks at PPQ 480), not “1–3 ticks”.

22. GLOSSARY
================================================================================

  Term                    Meaning
  ----------------------  -----------------------------------------------------
  SMF                     Standard MIDI File (.mid)
  PPQ                     Pulses per quarter note (ticks_per_beat)
  GM                      General MIDI programs / drum map
  Type 0 / Type 1         Single-track vs multi-track SMF
  Conductor               Type 1 track 0 — tempo / time / key map
  Role                    melody | chords | bass | drums
  Composition JSON        LLM schema → composer.py (text mode)
  Exact chords            parse_chord_symbol + exact.py → MidiEngine
  Humanize                Controlled timing/velocity/duration jitter
  Swing (API)             Off-beat delay fraction 0–1 (≈0.33 triplet)
  Swing (Studio MPC %)    50 straight, ≈66 triplet; converted before POST
  Solo                    Export only soloed roles (multi-solo OK)
  Mute                    Omit role from .mid (not a silent track)
  duplicate_score_meta    Opt-in Type 1 meta on every note track
